## Implications for determinism

- **Python sets are not ordered and the order changes per process.** Hash randomization is on by default for `str`/`bytes`, and "Changing hash values affects the iteration order of sets." Never iterate a set/frozenset (or anything derived from one, e.g. `set(...)` of node ids, symbols, spans) without an explicit `sorted(..., key=...)`. Fixing `PYTHONHASHSEED` in CI is a backstop, not a fix ("Python has never made guarantees about this ordering"). Hypothesis's own `@seed` docstring lists hash randomization as a nondeterminism source.
- **z3 unsat cores are neither minimal nor stable by default.** "Z3 does not guarantee that the unsat cores are minimal"; `smt.core.minimize`/`sat.core.minimize` default to `false` and only "minimize" (inclusion-wise), never "smallest". A naive `unsat_core()` -> explanation can change size and membership with parameters or version. Enable minimization or run your own deletion-based reduction, and sort/canonicalise the tracked literal names before emitting.
- **z3 has no documented determinism guarantee.** Set `smt.random_seed`/`sat.random_seed` explicitly (default 0), but the docs promise nothing about identical results across versions or builds (release notes mention "cross-compiler determinism" fixes). Wall-clock `timeout` is documented as non-deterministic; use `rlimit` ("deterministic resource limit") instead. Pin `z3-solver==5.1.0.0` and record the version in outputs.
- **`nx.topological_sort` order is "nonunique".** Use `lexicographical_topological_sort(G, key=...)` with a key that yields a total order (mixed str/int nodes raise `TypeError`). `find_cycle(source=None)` picks a source "arbitrarily", so the reported cycle can differ between runs/graph insertion orders; pass an explicit (sorted) source, or sort the reported edges. Remember both sort functions are generators: `NetworkXUnfeasible` surfaces during iteration, not at the call.
- **pdfplumber text is a function of tolerances, flags and the pinned pdfminer.six.** Output depends on `x_tolerance`/`y_tolerance`/`x_tolerance_ratio`, `layout` (experimental), `use_text_flow` (order "does not always appear to be logical"), `expand_ligatures` (default `True` since 0.9.0), `split_at_punctuation`, `dedupe_chars`. Each release re-pins `pdfminer.six` (0.11.10 -> 20260107), and 0.6.0 changed numeric precision of coordinates. Pin `pdfplumber==0.11.10`, fix every kwarg explicitly, persist `chars`/offsets, and hash the extracted text as a provenance check. No hyphenation handling is documented: de-hyphenation must be your own deterministic rule.
- **spaCy sentencizer is rule-based, but its defaults are version-bound.** The default `punct_chars` list and the `blank("en")` tokenizer rules are what determine `Span.start_char/end_char`; pin `spacy==3.8.16` and pass `punct_chars` explicitly so the boundary rule is in your code, not the library default.
- **Hypothesis determinism is conditional.** `derandomize=True` holds only "until you update Hypothesis, Python, or the test function", forces `database=None`, and is silently the default when a `CI` env var exists (so local and CI runs differ unless you `load_profile` explicitly). `@seed` overrides `derandomize`; timing, hash randomization and external state still break reproducibility. Use the built-in `ci` profile (`derandomize=True, deadline=None, database=None, print_blob=True`) or a named profile via `HYPOTHESIS_PROFILE`.
- **pydantic schemas and mypy strictness drift with versions.** `model_json_schema()` output (and the `union_format` option) can change between pydantic releases; `--strict`'s flag list "may change over time". Pin `pydantic==2.13.5` and `mypy==2.3.1` (or enumerate the strict flags explicitly). `extra='forbid'` is what makes model-output validation reject unexpected keys — keep it on for any schema an LLM fills.
- **hashlib.sha256 is guaranteed but "may nonetheless be missing or blocked in unusual environments"** (restricted/FIPS builds); fail fast at startup if `hashlib.sha256` is unavailable.
- **Not covered here:** the LLM call itself (anthropic 1.3.0) is outside the scope of these checks; nothing above makes model output deterministic.
