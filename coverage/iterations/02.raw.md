## 6. COMPOSITION COLLECTION — larger useful wholes

Each entry states the parts, **what passes between them**, **what must remain consistent**, and **which requirements are inherited**. Composition is recursive: several of these are components of later ones.

**C1 · Water evidence chain (E-03 + E-04 + E-01 + E-02).**
Parts: DataStream's WQX JSON schema; Open Waters submission software; EPANET; SWMM. Passes: monitoring records → validated JSON → EPA-coded WQX submission → federal record; separately, network models → simulated pressure/age/overflow. Must stay consistent: **the WQX version and EPA domain-value list** used by the schema (E-03 R2) and by the translation layer (E-04 R5); the monitoring location identity across observed and simulated worlds. Inherits: E-04 R6 activity-type validation; E-01 R5 "as is" disclaimer, which forbids treating simulated results as observed evidence. Emergent outcome: a utility can state, for one catchment, what was measured, what was modelled, and where the two disagree — which neither half supports alone.

**C2 · Repair impact ledger (S-01/S-02 + S-03 + S-04).**
Parts: ORDS-structured event records; the Restart weight/CO2e dataset; the EU repair obligations. Passes: product category key → per-item weight and CO2e → aggregated avoided-impact figure → evidence for policy. Must stay consistent: **ORDS category identifiers and the ORDS version** (S-02 R1, S-03 R1) — a category rename silently breaks every historical total. Inherits: S-03 R6 (much source data lacks CO2e/weight) and R3 (per-category quality evaluation), so every aggregate must carry a quality qualifier; CC BY-SA 4.0 from both datasets, which propagates to any derived ledger. Emergent outcome: repair groups can answer a regulator's question about real-world repairability with data, and the same categories feed S-04's score debate.

**C3 · Conformance-driven standards development (H-06 + H-04 + G-01/G-02).**
Parts: a conformance framework; reference implementations; a normative schema and a conformant toolkit. Passes: scenario steps → messages → per-step results → defect reports that split "implementation wrong" from "standard ambiguous". Must stay consistent: **the standard version under test** across scenarios, reference implementation and adopter. Inherits: H-04 R3 — the reference implementation has no authorisation, so conformance testing must never run against production data. Emergent outcome: a standards body learns of its own ambiguities before adopters ship, which is the reflexive value H-06 R2 already claims and G-01/G-02's conformance claim currently lacks.

**C4 · Machine-readable regulation loop (H-01 + J-06 + N-02/N-04).**
Parts: the MDS Policy API; the UK open-standards selection process; OCDS core and its extensions. Passes: a user problem → a selected standard → published machine-readable policy → operator compliance → procurement records of the contracts that implement it. Must stay consistent: the **problem statement** from J-06 R1 through to the adopted standard; geography and organisation identifiers shared between policy and contract. Inherits: H-01 R6's 20-minute publication lead time (a hard timing contract), and N-04's additivity constraint for jurisdiction-specific fields. Emergent outcome: a city can trace a rule from the citizen problem that motivated it to the contract that delivers it.

**C5 · Building information spine (F-03 + F-04 + L-03 + N-01).**
Parts: bSDD verified dictionaries; an IDS ruleset for BIM-BEM; BuildingSync audit records; Brick operational metadata. Passes: verified concept definitions → model-checking rules → audit findings and measures → live operational points. Must stay consistent: **the term identity for a piece of equipment across design, audit and operation** — bSDD's class, the IFC entity, the BEDES term BuildingSync links to, and the Brick class. Inherits: F-03 R13 (unit must match dimension) and R14 (do not recreate IFC properties); L-03 R7 (examples must stay valid); N-01 R2 (relationship minimality). Emergent outcome: a measure proposed in an audit can be checked against the design model and verified against operational data — the three today live in unconnected tools.

**C6 · Portable evidence for health decisions (Q-04 + Q-05 + Q-07).**
Parts: US Core profiles; CARIN Blue Button consumer claims; OMOP CDM and its analysis tools. Passes: clinical records → profiled FHIR resources → consumer-visible claims; separately, site data → OMOP → portable cohort definitions → summary results. Must stay consistent: **patient identity within a site, and concept identity across sites** (Q-07 R2 vocabulary version). Inherits: Q-04 R3 Must-Support obligations; Q-05's caregiver delegation scope; Q-07's constraint that analyses travel and data does not. Emergent outcome: a claim a patient can read and a cohort a researcher can run are derived from the same underlying record without the record leaving its custodian.

**C7 · Identity continuity across a shutdown (U-04 + O-04 + O-06 + J-04).**
Parts: a decommissioning humanitarian identity provider; a national identity provider; a wallet presentation protocol; an agent-protocol authorization design. Passes: subject identifiers and account mappings from the retiring provider to a successor; presentations for credentials the successor cannot itself assert. Must stay consistent: **the subject identifier per relying party** — the thing that actually breaks at U-04 R4's 31 December 2025 cut-off. Inherits: J-04 R2 (clients must not hold third-party credentials); O-06 R2 (three credential formats). Emergent outcome: a migration plan in which relying platforms keep working, which no single source provides.

**C8 · Agricultural decision provenance (A-01 + A-05 + A-06 + A-03's discipline).**
Parts: BrAPI trial and germplasm data; ADAPT production data; Modus lab results. Passes: work order → sample → analyte result → agronomic recommendation → field operation record → observation. Must stay consistent: **sample identity from order to result** (A-06 R5), **germplasm and study identity** (A-01 R2/R5), and **unit abbreviations** (A-05 R1) across all three. Inherits: A-06's requirement that method identity accompany every analyte; A-05's data-only constraint, so the composition must not smuggle in a toolkit dependency. Emergent outcome: a recommendation can be traced back to the specific sample, method and trial that justify it.

**C9 · Preservation-grade cultural publishing (R-02 + R-05 + R-06 + X-03).**
Parts: OCFL storage layout; a museum IIIF service; a manifest editor; TEI-encoded texts. Passes: source images and transcriptions → OCFL object versions → IIIF manifests → viewers. Inherits: R-02's self-describing-storage requirement; R-06's obligation that exports open in independent viewers; X-03's prose-schema parity. Emergent outcome: a citation that still resolves after the publishing software is gone — the actual preservation promise.

**C10 · Grid change with a safe floor (D-02 + D-05).**

Emergent outcome: a change at the substation and a change at the inverter can be reasoned about as one system, with a defined safe state when the link fails.

**C11 · Generator — Conformance-Pack Builder (configurator).**
Generator: given (i) a normative schema or API description, (ii) a party-role model, and (iii) a set of acceptance criteria, it emits a runnable conformance pack — scenarios, synthetic fixtures, a counterparty simulator, and a report template that separates implementation defects from standard ambiguities. ## 7. STRESS COLLECTION *(separately labeled hypothetical variations — one per selected case; each states the changed condition and its consequences. No inherited requirement is deleted; where a stress makes one unsatisfiable, that is stated.)*
